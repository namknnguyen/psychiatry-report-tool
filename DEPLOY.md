# Deploying PsychReport on Render

This publishes PsychReport as a **public demonstration with fictional data only**.
Allow about 15 minutes the first time.

> **Before you start — what this deployment is.** Anyone with the URL can sign in with the
> demo accounts shown on the sign-in page. Visitors share the same demo data and can see
> each other's drafts. Everything is erased whenever the service restarts or redeploys.
> Never enter real patient information. For what real clinical use would require, see
> "Before real use" in the README.

---

## What you need

- A GitHub account.
- A Render account (<https://render.com>). Signing up with GitHub is the simplest option.
- `git` on your Mac. Optionally the GitHub CLI (`gh`), which saves a few steps.

**Which Render plan?** The free instance works. It sleeps after about 15 minutes without
traffic and takes roughly a minute to wake on the next visit, and generating reports is a
few seconds slower because the instance has a small CPU share. A paid Starter instance stays
awake and responds faster. Check Render's pricing page for current plans. You can change the
plan later without redeploying.

## Step 1 — Put PsychReport in its own repository

Render deploys a Git repository and reads `render.yaml` from its root. Right now `psychreport/`
sits inside your `kg_research_sep2` research repository, which has no remote and holds unrelated
code. Copy it to a standalone folder so the research repository is left untouched:

```bash
cp -R /Users/namnguyen/kg_research_sep2/psychreport ~/psychreport
```

Create the repository and the first commit:

```bash
cd ~/psychreport && git init -b main && git add . && git commit -m "PsychReport demo"
```

Confirm no local database was included — this should print nothing:

```bash
cd ~/psychreport && git ls-files | grep -E '^data/|__pycache__'
```

## Step 2 — Push it to GitHub

**With the GitHub CLI** (creates a private repository and pushes in one go):

```bash
cd ~/psychreport && gh repo create psychreport --private --source=. --push
```

**Without the CLI:**

1. Go to <https://github.com/new>.
2. Repository name: `psychreport`. Choose **Private**. Leave *Add a README*, *.gitignore* and
   *license* unticked — the repository must start empty.
3. Click **Create repository**.
4. Push, replacing `YOUR-USERNAME`:

```bash
cd ~/psychreport && git remote add origin https://github.com/YOUR-USERNAME/psychreport.git && git push -u origin main
```

A private repository is fine; Render can deploy it once you grant access in the next step.

## Step 3 — Connect Render to GitHub

1. Sign in at <https://dashboard.render.com>.
2. If you did not sign up with GitHub, connect it from your account settings.
3. When GitHub asks which repositories Render may access, choose **Only select repositories**
   and pick `psychreport`.

## Step 4 — Deploy with the Blueprint

The repository includes `render.yaml`, which describes the whole service, so there is nothing
to type in.

1. In the Render Dashboard, click **New** → **Blueprint**.
2. Select the `psychreport` repository and click **Connect**.
3. Give the Blueprint a name if asked (anything, e.g. `psychreport`). Render lists one resource:
   a web service named **psychreport-demo**.
4. Click **Deploy Blueprint** (labelled **Apply** in some versions of the dashboard).

What the Blueprint configures, so you know what to expect:

| Setting | Value | Why |
|---|---|---|
| Runtime | Python, `PYTHON_VERSION=3.11.9` | The version the test suite runs on |
| Build command | `pip install -r requirements.txt` | Installs nothing — the app is standard library only |
| Start command | `python -m app.main --hosted` | Binds `0.0.0.0:$PORT`, Secure cookies, HSTS, fresh demo data on every start |
| Health check | `/healthz` | Render waits for this before sending traffic |
| `PSYCHREPORT_PASSPHRASE` | generated by Render | Encryption key passphrase; never committed. The app refuses to start without it |
| Auto-deploy | on | Every push to `main` redeploys |

## Step 5 — Watch the first deploy

Open **psychreport-demo** → **Logs**. A successful start ends with a banner like:

```
  Serving   http://0.0.0.0:10000/   [HOSTED PUBLIC DEMO - reseeded on start]
  ...
  Ctrl-C to stop.
```

The service shows **Live** once `/healthz` responds. The first build usually takes a few minutes.

## Step 6 — Check it

Your address is shown at the top of the service page, normally
`https://psychreport-demo.onrender.com` (Render adds a suffix if that name is taken).

1. Open `https://YOUR-SERVICE.onrender.com/healthz` — it should show `ok`.
2. Open the main address. The sign-in page shows an amber banner saying this is a public demo.
3. Click **Take the guided tour**. It signs in as Dr. Chen and walks through the app in 15 steps.
4. After the tour, open **Compliance & audit**: *Network exposure* should show a warning that
   reads "Public demonstration deployment".

To confirm the security headers from your terminal:

```bash
curl -sI https://YOUR-SERVICE.onrender.com/ | grep -iE 'strict-transport|content-security'
```

## Alternative — create the service by hand

Use this instead of Step 4 if you prefer not to use a Blueprint.

1. **New** → **Web Service** → select the `psychreport` repository.
2. Fill in:
   - **Language:** Python 3
   - **Branch:** `main`
   - **Root Directory:** leave blank
   - **Build Command:** `pip install -r requirements.txt`
   - **Start Command:** `python -m app.main --hosted`
   - **Instance Type:** Free (or a paid instance)
3. Under **Environment Variables**, add:
   - `PYTHON_VERSION` = `3.11.9`
   - `PSYCHREPORT_PASSPHRASE` = a long random value. Generate one locally:

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(32))"
```

4. Under **Advanced**, set **Health Check Path** to `/healthz`.
5. Click **Create Web Service**, then continue from Step 5.

## Updating the deployment

Edit the code in `~/psychreport`, then commit and push. Render redeploys automatically, and the
demo data is reset as part of the restart.

```bash
cd ~/psychreport && git add . && git commit -m "Update demo" && git push
```

If you keep editing the original copy inside `kg_research_sep2`, copy the changes across first —
the two folders are independent after Step 1.

## Troubleshooting

| What you see | Cause and fix |
|---|---|
| Logs say `REFUSING TO START: hosted mode requires PSYCHREPORT_PASSPHRASE` | The variable is missing. Blueprint deploys generate it; for a hand-made service add it under **Environment** and redeploy. |
| Deploy fails with *no open ports detected* | The start command is missing `--hosted`, so the app bound only to 127.0.0.1. Set it to `python -m app.main --hosted`. |
| Deploy stuck waiting on the health check | Confirm **Health Check Path** is `/healthz`, not `/`. |
| First page load takes about a minute | A free instance was asleep. Expected; a paid instance stays awake. |
| "Too many failed sign-in attempts from this connection" | Ten failed sign-ins from your connection within 15 minutes. Wait, or use **Take the guided tour**, which signs in for you. Other visitors are unaffected. |
| Patients or reports you created have disappeared | The service restarted or redeployed. By design, nothing a visitor enters is kept. |
| Build picks a different Python version | Make sure `PYTHON_VERSION` is set to `3.11.9`. |

## Taking it down

Service page → **Settings** → **Delete Web Service**. If you deployed with a Blueprint, you can
also delete the Blueprint from the **Blueprints** page.
